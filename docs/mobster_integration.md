# MOBSTER integration route

MOBSTER is an R package. CloneTrace treats it as an optional external analysis rather than
shipping an R runtime, an `rpy2` dependency, or a Python wrapper in this phase. A seeded
MOBSTER smoke fit has since been run in the development environment; its scope and limits are
recorded below.

## Requirements and license

- Install R 4.0 or newer and MOBSTER in a separate R environment. Follow the
  [upstream installation instructions](https://github.com/caravagnalab/mobster#installation).
- MOBSTER is licensed GPL-3 according to its upstream
  [package description](https://github.com/caravagnalab/mobster/blob/master/DESCRIPTION).
  Check license compatibility before bundling or distributing it with CloneTrace.
- For a reproducible analysis, pin the MOBSTER commit/package version and record `sessionInfo()`.
  The upstream README currently documents `devtools::install_github("caravagnalab/mobster")`;
  that floating install is not a reproducible version pin.

The smoke run used MOBSTER commit
`85c898f087b46e15f79144bf57bdc019678e2481` (version 1.0.0). Its GitHub dependencies were
resolved to `easypar` `226e2162ee6eeac44175ab6fb33baf5d5410b6ad`, `pio`
`2cfe575ba8c41905fc43540fd489e79b1bac0d5e`, `dndscv`
`1bd3b1503d9f79b0518bcdadf4034389207a8d48`, and `ctree`
`d012b580882a26364c7fe804f25bc1f58edfa4c1`. The R version and package versions are retained
in the run's `sessionInfo()`.

## Input preparation

`mobster::mobster_fit()` accepts a data frame with a `VAF` column. The upstream function
documentation says this must already be adjusted for tumor purity and copy-number status.
Prepare one row per mutation from canonical mutation counts and the corresponding purity,
copy-number, and multiplicity estimates. CloneTrace exposes
`clonetrace.qc.estimate_ccf_from_vaf()` for the diploid-normal purity/CN/multiplicity model.

Do not silently cap adjusted values above 1. Such a value flags sampling noise or a model/data
mismatch; inspect and document any decision to exclude the observation before running MOBSTER.
This project has not yet defined cohort-wide exclusion rules.

Example shape for the R input:

```r
vaf_data <- read.delim("mobster_vaf.tsv", check.names = FALSE)
stopifnot(all(c("mutation_id", "VAF") %in% names(vaf_data)))

fit <- mobster::mobster_fit(
  vaf_data,
  K = 1:3,
  tail = TRUE,
  samples = 5,
  parallel = FALSE,
  seed = 123,
  description = "CloneTrace sample"
)

saveRDS(fit, "mobster_fit.rds")
writeLines(capture.output(sessionInfo()), "mobster_session_info.txt")
```

## Verified smoke run

On 2026-11-28, MOBSTER completed a fit on 80 mutations generated by the CloneTrace simulator
(seed 42, depth 1000, purity 0.8, three clones, branching topology, no copy-number events).
Observed VAFs were adjusted to CCF using total copy number 2 and multiplicity 1; adjusted
values ranged from 0.1651 to 0.6015, with no exclusions or clipping. The fit used
`K = 1:3`, `tail = TRUE`, `samples = 5`, and seed 123. It converged and selected one Beta
component plus a Pareto tail (31% of mutations assigned to the tail). This is an execution
smoke test on simulated data, not a biological result or evidence that the selected component
count recovers the simulated clone count.

The fit object retained the mutation IDs and an 80-by-2 `best$z_nk` posterior matrix in this
run; row identity and posterior row sums were checked. The fit, input, package versions, and
session information were retained as session artifacts, not checked into the repository.

MOBSTER's `K` controls the number of Beta components; its optional Pareto tail models neutral
within-clone evolution and must not be reported as a clone. MOBSTER's fitted component
uncertainty and model-selection outputs should be retained when available.

## CloneTrace interoperability status

This route does not yet convert MOBSTER fit objects into CloneTrace mutation assignments. The
smoke run exposed `best$data` and `best$z_nk`, but a version-pinned extraction path has not been
validated across fit conditions and edge cases. Before adding it to the shared `cluster` CLI or
consensus pipeline:

1. Implement a version-pinned R script/adapter that exports mutation IDs, cluster IDs,
   assignment confidence, and any supported prevalence uncertainty to a documented TSV.
2. Verify row identity and uncertainty fields against the input; fail on missing, duplicate,
   or out-of-range results rather than manufacturing assignments.
3. Test the adapter on a seeded CloneTrace simulation and a supported real sample.
4. Record the R version, MOBSTER commit, seed, model-selection settings, and exclusions.
